# Compartmentalise Plan — making Starve No More AI-friendly at small context

**Goal:** let an AI agent work on any part of this repo while reading as few
tokens as possible. The lever is *locality*: an agent should be able to find the
right file from an index, open only that file (a few hundred lines, not a few
thousand), make the change, and verify it — without ever loading the 1,500-line
design doc or the 1,600-line test module "just in case".

**Guiding principles**
- **Index over scan.** Every "which file do I touch?" question should be
  answerable from a short routing table, not by grepping the tree.
- **One concern per file.** Target ≤ ~500 lines per source file; split anything
  materially larger along its natural seams.
- **Scoped context.** A task confined to `lua/` should load `lua/`-local
  guidance, not the whole repo's conventions.
- **Keep generators honest.** Splitting must not break the build order or the
  freshness tests. Regenerate `SYMBOLS.md` + `.luacheckrc` after any Lua move.

**How to use this file:** work top-to-bottom — phases are ordered by
value-per-effort. Each item is independently shippable; commit after each so the
diffs stay reviewable. Check boxes as you go.

## Phase 2 — Split the large Lua modules

**Safe because** every `lua/*.lua` file is concatenated into one save and all
functions live in a shared global namespace — there are no `require`s to rewire.

**Critical constraint:** `scripts/build_save.py` concatenates in the explicit
`LUA_LOAD_ORDER` list, then appends any *unlisted* `.lua` files **last, in
sorted order**. Data/definition files must load before their consumers, so:
> **When you split a file, add every new part to `LUA_LOAD_ORDER` explicitly,
> in the correct position.** Never rely on the auto-pickup for a file that
> defines something another file uses at load time.

After each split: `python scripts/generate_symbol_index.py` (refreshes
`SYMBOLS.md` + `.luacheckrc`), then `python -m pytest tests`.
